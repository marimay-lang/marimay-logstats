# Находки волны потоковых CLI

- **Исправлено, std/runtime:** у файла отсутствовал общий bounded readLine.
  D101 разделяет обработку строк stdin/files, ограничивает каждую строку и
  сохраняет общий курсор алиасов; приложение не читает весь файл в []byte.
- **Исправлено, native:** JSON-кодирование свежих записей внутри цикла читало
  поля первой записи. Минимум: цикл создаёт `Row { value: key, count }` из Map
  и вызывает `json.encode`. VM меняла пары, native повторял первую. Backend
  теперь проверяет текущую managed reference и обновляет child-array hints.
  Исправление проверяется на исходном count, не обходится сменой кода приложения.
- **Открыто, checker, blocking для корректных diagnostics:**
  `fn f(r: Result<void,int>):int { return match r { Ok(value)=>0, Err(e)=>e, }; }`
  завершается внутренним статусом 70 без T0002. Void нельзя хранить в имени;
  ожидается такой же диагностируемый отказ, как у обычного named binding.
  Здесь используется нормативное `Ok(_)`. Владелец: enum-pattern binding.
- **Наблюдение, source ergonomics:** Map loop принимает одно имя tuple;
  используется `for pair in values { match pair { (key, value) => ... } }`.
  Обобщённое связывание в заголовке for не реализовано. Это не новая семантика
  приложения; при расширении syntax нужна общая parser/checker/formatter работа.
- **Осознанно:** put/add возвращают bool, который уже известен после проверки
  лимита. `const _ = operation(...).mapError(...) ?` отбрасывает только bool;
  ошибка сохраняется и проходит к пользователю.
- **Открыто:** escaping mutable-capture warning D098, CLI0 named budgets,
  claimed-platform evidence и обычная установленная сборка на всех Tier 1.

Идеи и страницы из книги Владимирова для этого изменения не использовались.
